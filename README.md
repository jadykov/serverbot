# Telegram-бот на Node.js + TypeScript с нейросетями

Учебно-боевой пример телеграм-бота: несколько команд, подключение сразу нескольких
нейросетей (текст и картинки), Docker, health-check, graceful shutdown и подробные
комментарии в коде на русском языке.

* **Текст и картинки на вход** — Google Gemini, бесплатный тариф. Модели идут
  цепочкой: если у первой кончилась дневная норма, запрос молча подхватывает следующая.
* **Генерация картинок** — OpenRouter. У Google все модели генерации изображений
  недоступны на бесплатном тарифе.
* **Песни с вокалом** — GoAPI, модель Ace-Step. Вместе с картинками это два
  платных места в боте; всё остальное бесплатно.
* **Тестовые команды** в стиле «Марко-Поло» — чтобы за 5 секунд убедиться, что бот жив.

> **Бот работает через long polling** — сам опрашивает Telegram по исходящему
> соединению. Поэтому ему не нужны ни домен, ни белый IP, ни сертификат, ни
> проброшенные порты: он одинаково запускается дома за NAT, в WSL и на любом VPS.

## Команды бота

| Команда | Что делает |
| --- | --- |
| `/start`, `/help` | Приветствие и справка. `/start` заодно включает бота, если в разделе его выключили |
| `/stop` | Замолчать в этом разделе. Обратно — `/start`. Может любой участник, кириллицей — `/стоп` и `/старт` |
| `/гем <запрос>` | Запрос к Gemini цепочкой, выбранной для раздела. Латинский синоним — `/gem` |
| `/гем !контекст <задача>` | То же, но сильной цепочкой, минуя настройку раздела. Ответ — одним сообщением |
| `/гем !контекст md\|txt\|html <задача>` | Тот же ответ сильной цепочки, но файлом — для разборов, которые в чат не влезают |
| `/гем !нарисуй <описание>` | Уточнить замысел вопросами и нарисовать через OpenRouter (**платно**, не больше 2 в день на человека) |
| `/гем !расшифруй` <i>(реплаем на голосовое)</i> | Послушать голосовое и ответить по существу. Вместо `!расшифруй` можно сразу задать вопрос по записи. В личке достаточно просто наговорить |
| `/гем !трек <описание>` | Написать песню с вокалом через Ace-Step (**платно**, не больше 2 в день на человека). Стиль и слова бот соберёт сам |
| `/гем !скажи <текст>` | Озвучить текст голосом. Голос и манеру можно заказать кавычками: `!скажи «низкий» …`. Без текста — сообщение, на которое ответили реплаем, иначе последний ответ бота |
| `/гем !найди <что искать>` | Поиск по переписке раздела — по смыслу, а не по словам |
| `/гем !сеть <вопрос>` | Ответ со свежими данными из интернета, со ссылками на источники (**платно**, не больше 10 в день на человека) |
| `/гем !файл <что сделать>` | Прислать ответ отдельным файлом: `.md`, `.html`, `.svg`, `.csv`… Реплаем — выгрузит сообщение |
| `/гем !где здесь <предмет>` | В подписи к фотографии или реплаем на неё: обвести найденное рамкой прямо на снимке |
| `/гем !личка` <i>(реплаем)</i> | Переслать сообщение — файл, снимок, текст — в личный диалог с ботом |
| `/ping` | «Pong» + реальная задержка до Telegram API + аптайм |
| `/marco` | Отвечает `Polo!` — простейшая проверка живости |
| `/polo` | Отвечает `Marco!` |
| `/test` | Самодиагностика: связь с Telegram + готовность провайдеров |
| `/test ai` | То же самое плюс настоящий короткий запрос к нейросети |
| `/whoami` | Ваши user id и chat id (нужны для `ADMIN_IDS`) |
| `/status` | Режим работы, аптайм, память, активные провайдеры |

**Слова-команды пишутся с восклицательным знаком** — и это не украшение.
Без него они воровали обычные вопросы: «/гем скажи, что такое рекурсия» уходило
в озвучку вместо ответа, «/гем найди ошибку в этом SQL» — в поиск по архиву
переписки, а «/гем нарисуй схему словами» тратило деньги на картинку. Все эти
слова слишком обычны для русской речи, чтобы значить команду просто так.
Забыли знак — бот ответит на вопрос как на вопрос и подскажет синтаксис.

**Сами слова — только по-русски.** Латинские формы (`!draw`, `!say`, `!context`,
`!find`, `!file`) убраны: держать в голове два написания одного и того же
приходилось всем, а пользовался ими никто. Команда при этом по-прежнему
существует в двух видах, и слова работают после любой из них одинаково —
`/гем !нарисуй кота` и `/gem !нарисуй кота` дадут один результат.

Дополнительно: слово **marco** обычным сообщением (без слэша) тоже получит `Polo!`.

Обычные сообщения запросом к нейросети **не считаются** — обращаться к боту нужно
командой. Так случайная переписка не тратит квоту API.

Единственное исключение — **ответ реплаем на сообщение бота**: это продолжение
разговора, и команда для него не нужна ни в личке, ни в группе. Цитата реплики
подмешивается в запрос (но не в историю), поэтому бот понимает, на какую именно
из своих реплик ему отвечают, даже если она давняя и из истории уже вытеснена.

**Картинку можно просто прислать** — бот её разберёт («что на фото», текст со скриншота).
В личке достаточно самой картинки, в группе нужна подпись с командой:
`/гем что здесь написано`. Альбом из нескольких снимков уходит одним запросом,
а не отдельным на каждый.

Ответы Gemini приходят с разметкой: жирный, курсив, списки, ссылки, инлайн-код и
блоки кода с подсветкой языка (см. [Разметка ответов](#разметка-ответов)).

## Структура проекта

```
serverbot/
├── src/
│   ├── index.ts               # точка входа: старт polling и graceful shutdown
│   ├── bot.ts                 # сборка бота: middleware, команды, обработка ошибок
│   ├── server.ts              # маленький HTTP-сервер только с /health
│   ├── config.ts              # вся конфигурация из переменных окружения
│   ├── logger.ts              # логгер (JSON в проде, цветной в разработке)
│   ├── types.ts               # интерфейсы провайдеров, сессия, типы ошибок
│   ├── format.ts              # Markdown нейросети → разметка Telegram + нарезка
│   ├── utils.ts               # таймауты, «печатает…», длительности
│   ├── commands/
│   │   ├── basic.ts           # /start /help /ping /marco /test /whoami /status
│   │   ├── ai.ts              # /гем: слова-переключатели, картинки, голосовые, песни
│   │   ├── draw.ts            # разговор перед рисованием: вопросы, кнопки, подтверждение
│   │   ├── file.ts            # «!файл»: ответ отдельным файлом, вплоть до HTML с SVG
│   ├── models.ts              # цепочки моделей и их назначение
│   ├── media.ts               # скачивание файлов из Telegram, склейка альбомов
│   ├── middlewares/
│   │   ├── logging.ts         # лог каждого апдейта и времени обработки
│   │   ├── reply.ts           # ответы реплаем и в нужный топик форума
│   │   ├── rateLimit.ts       # защита от спама
│   │   └── searchIndex.ts     # запоминает переписку для поиска
│   └── services/
│       ├── registry.ts        # реестр провайдеров — единственное место для новых ИИ
│       ├── chain.ts           # перебор цепочки моделей при отказе
│       ├── gemini.ts          # Google Gemini
│       ├── gemini-tts.ts      # озвучка текста голосом
│       ├── goapi-music.ts     # песни с вокалом: Ace-Step через GoAPI (платно)
│       ├── song-prompt.ts     # стиль и слова песни: сборка запроса к Ace-Step
│       ├── voice.ts           # голосовые на вход: перекодировка под форматы Google
│       ├── ffmpeg.ts          # общая обвязка вокруг ffmpeg (озвучка и голосовые)
│       ├── search-index.ts    # архив переписки и поиск по смыслу
│       ├── pointing.ts        # «где здесь …»: координаты предметов и рамки
│       ├── documents.ts       # присланные книги и статьи: разбор и предел размера
│       ├── openai-compatible.ts # OpenAI / OpenRouter / DeepSeek / Ollama…
│       ├── openrouter-image.ts  # генерация картинок (платно)
│       ├── krea-prompt.ts     # наводящие вопросы и сборка промпта по правилам Krea
│       └── daily-quota.ts     # дневные нормы на человека: картинки и треки
├── Dockerfile                 # multi-stage: dev / build / runtime
├── docker-compose.yml         # production, сборка из исходников
├── docker-compose.dev.yml     # разработка с hot-reload
├── docker-compose.deploy.yml  # запуск готового образа из GHCR
├── .github/workflows/
│   └── docker-publish.yml     # автосборка и публикация образа в GHCR
└── .env.example               # шаблон конфигурации
```

**Главная идея архитектуры:** бот не знает, с какой нейросетью работает. Он видит только
интерфейсы `TextProvider` и `ImageProvider` из `src/types.ts`. Чтобы добавить ещё одну
модель, достаточно написать класс и вписать его в `src/services/registry.ts`.

## Шаг 0. Получаем ключи

### 1. Токен бота (обязательно)

1. Откройте в Telegram [@BotFather](https://t.me/BotFather) → `/newbot`.
2. Придумайте имя и username (должен заканчиваться на `bot`).
3. Скопируйте токен вида `1234567890:AAH...`.

Полезно там же: `/setdescription`, `/setuserpic`, а для работы в группах —
`/setprivacy` → `Disable`, иначе бот не увидит обычные сообщения в группе.

### 2. Google Gemini (текст, бесплатный тариф)

Ключ: <https://aistudio.google.com/apikey> → `GEMINI_API_KEY`.

Посмотреть модели, доступные именно вашему ключу:

```bash
curl -s -H "x-goog-api-key: $GEMINI_API_KEY" \
  https://generativelanguage.googleapis.com/v1beta/models | grep '"name"'
```

Имена моделей меняются: Google периодически переименовывает версии и закрывает
старые. Поэтому цепочки вынесены в `.env` — `GEMINI_CHAIN_MAIN` и
`GEMINI_CHAIN_THINK`. Если бот пишет «модель недоступна», поправьте их, сверившись
со своим списком лимитов: <https://aistudio.google.com/rate-limit>.

**Норм у бесплатного тарифа три, и жмёт обычно не та, о которой думают.**
Дневная (запросы в сутки), минутная по запросам и минутная по токенам — причём
в токенную входит и вопрос, и ответ. У Gemma, которая ведёт основную цепочку,
дневной запас огромный, а минутный тесный: 16 000 токенов. Поэтому потолок
ответа задан для каждой цепочки свой — `GEMINI_MAX_OUTPUT_MAIN` и
`GEMINI_MAX_OUTPUT_THINK`, — и просить у модели больше её минутного бюджета
бот не станет.

Дневная норма лечится цепочкой: кончилась у первой модели — отвечает следующая.
Минутная так не лечится, её можно только не превышать.

### 3. OpenRouter (генерация картинок, платно)

Ключ и баланс: <https://openrouter.ai/keys> → `OPENROUTER_API_KEY`.

Бесплатно нарисовать нечем. У Google все модели генерации изображений помечены
`Not available` для бесплатного тарифа. В веб-интерфейсе AI Studio картинки
рисуются бесплатно, но через API те же модели требуют включённого биллинга;
на этом расхождении обычно и путаются.

Проверено запросами к API 17 августа 2026, если соберётесь сверяться:

* **Imagen с API снят.** На `imagen-4.0-fast-generate-001`, `imagen-4.0-generate-001`
  и `imagen-4.0-ultra-generate-001` приходит `404` с прямым текстом «This model is
  no longer available. Please update your code to use `models/gemini-3.1-flash-image`».
  `imagen-3.0-generate-002` не находится тоже;
* **живы `gemini-3.1-flash-image`, `gemini-3-pro-image-preview` и `gemini-2.5-flash-image`**,
  но на бесплатном ключе все три отвечают `429` со ссылкой на биллинг — норма
  у них не «кончилась», а нулевая с самого начала. Вызываются они обычным
  `generateContent` с `responseModalities: ['IMAGE']`, а не отдельным `:predict`,
  как это было у Imagen.

Точную стоимость каждого вызова OpenRouter возвращает сам, и бот показывает
её в подписи под картинкой. Замерено на квадрате 1024×1024:

| | `krea/krea-2-medium-turbo` | `openai/gpt-image-1-mini`, качество `low` |
| --- | --- | --- |
| Цена вызова | **$0,015** (~66 картинок на доллар) | **$0,0022** (~450 картинок на доллар) |
| Время | 17 с | ~10 с |
| Файл | png, 1,5 МБ | jpeg, 50 КБ |

Krea в семь раз дороже — это плата за рисунок, а не за иллюстрацию: фактуру
бумаги, затёки, живой мазок. Если важнее объём, а не картинка, дешёвая модель
возвращается одной строкой в `.env`.

Поэтому у рисования есть **дневная норма — 2 картинки на человека**
(`IMAGE_DAILY_LIMIT`). Рейт-лимит для этого не годится: он считает запросы
в минуту и защищает от зажатого Enter, а тут вопрос денег, а не частоты.
Остаток бот показывает в подписи под каждой картинкой, а упёршемуся в норму
сообщает, через сколько она обновится. Тонкости:

* день **календарный**, по часовому поясу `IMAGE_DAILY_LIMIT_TZ` — иначе
  в контейнере с UTC норма обновлялась бы в три часа ночи по Москве;
* счётчик лежит в `SESSION_DIR/image-quota.json` и **переживает рестарт**:
  держи мы его в памяти, лимит обходился бы просьбой перезапустить бота;
* слот занимается до генерации и возвращается, если картинка не вышла, —
  за ошибку провайдера норма не списывается;
* **исключений нет**: норма одинакова для всех, включая админов. Рейт-лимит
  защищает бота от спама, и там админам поблажка уместна, а норма делит общий
  кошелёк — поблажка в ней означала бы просто «кому-то можно больше»;
* `IMAGE_DAILY_LIMIT=0` снимает ограничение вовсе.

### 4. GoAPI (песни с вокалом, платно)

Ключ и баланс: <https://goapi.ai> → `GOAPI_API_KEY`. Заголовок у них свой,
`X-API-Key`, а не `Authorization: Bearer` — бот это учитывает.

Бесплатно спеть тоже нечем, и по той же причине, что с картинками: Gemini
музыку не пишет вовсе, а Lyria у Google живёт в Vertex AI — с биллингом,
сервисным аккаунтом и совсем другим способом аутентификации, то есть не тем
ключом, которым работает весь остальной бот.

Модель — **Ace-Step**, открытая, и у посредника она стоит дешевле всех
остальных с вокалом: **$0,0005 за секунду готового звука**. Считается
длительность, а не запрос, поэтому цена ровно пропорциональна: полминуты —
$0,015, десять секунд — полцента. Стартовых $0,5, которые GoAPI даёт при
регистрации, хватает примерно на **три десятка треков по 30 секунд**.

Отсюда настройки по умолчанию: `TRACK_MAX_DURATION=30` и `TRACK_DURATION=30`
при `TRACK_DAILY_LIMIT=2`. Потолок выбран по кошельку, а не по пределу модели
(240 секунд): полминуты стоят столько же, сколько картинка. А длительность
по умолчанию равна потолку намеренно — будь она больше, каждый запрос молча
урезался бы, и это было бы худшим видом ограничения.

Норма считается отдельно от картинок, в `SESSION_DIR/track-quota.json`: платятся
они разным сервисам разными деньгами, и общий счётчик означал бы, что
нарисованный кот отнимает песню. Всё остальное в норме устроено так же, как
у картинок, — календарный день, слот возвращается при неудаче, исключений
для админов нет.

**Чего дневная норма не сторожит, так это баланса.** Она делит день, а не
кошелёк: пятеро человек по два трека — это $0,3 за вечер. Следить за остатком
приходится на goapi.ai; когда деньги кончатся, бот честно скажет об этом
вместо трека.

### Файлы от бота

`/гем !файл смета на ремонт кухни` присылает не сообщение, а файл. Нужно это
там, где сообщение неудобно: у Telegram потолок 4096 знаков, длинный ответ
приезжает пачкой кусков, и сохранить его нельзя.

```
/гем !файл смета на ремонт кухни          → smeta-na-remont-kuhni.md
/гем !файл html график продаж по кварталам → grafik-prodazh.html
/гем !файл csv список задач с дедлайнами   → spisok-zadach.csv
/гем !файл  (реплаем на сообщение)         → выгрузит его как есть
```

**Формат выбирается, а не назначается.** Сильнее всего явное слово первым
в запросе (`md`, `txt`, `html`, `svg`, `csv`, `json`, `py`, `js`, `ts`, `sh`,
`sql`), потом догадка по содержимому — страница, SVG, JSON или блок кода
с языком, — и только в последнюю очередь умолчание `.md`. Markdown, а не
`.txt`, потому что модель пишет разметкой: в простом тексте звёздочки
и решётки остались бы мусором.

**HTML получается настоящий и самодостаточный.** Модель просят держать стили
в `<style>`, а схемы — inline SVG, без единой внешней ссылки: файл открывается
в браузере без интернета. Проверено живьём — на запрос «страница с графиком
продаж по кварталам» пришли 6,6 КБ с четырьмя столбиками `<rect>`,
четырнадцатью подписями и ровно теми числами, что были в запросе.

**Длинный ответ можно получить файлом, не меняя вопроса.** Это другой случай,
чем `!файл`: там модель пишет сразу содержимое файла, здесь — отвечает как
обычно, со всей историей раздела, а файл собираем мы сами из готового ответа.

Разделение простое: **в чат — одно сообщение, файлом — сколько нужно.**

```
/гем !контекст md разбор архитектуры бота    → razbor-arhitektury-bota.md
/гем !контекст txt почему падает сборка       → pochemu-padaet-sborka.txt
/гем !контекст html план миграции на новый VPS → plan-migracii.html
```

Форматов ровно три, и каждый — это способ упаковки, а не заказ на содержимое:

| Формат | Что происходит с ответом |
| --- | --- |
| `md` | уходит как есть: модель и так пишет разметкой |
| `txt` | разметка снимается, ссылки разворачиваются в «текст (адрес)», код остаётся нетронутым |
| `html` | собирается настоящая страница: заголовки, списки, цитаты, блоки кода, тёмная тема по настройке системы. Без единой внешней ссылки — открывается с флешки |

Заодно поднимается потолок ответа: вместо чатового потолка цепочки берётся
`FILE_ANSWER_MAX_OUTPUT_TOKENS` (по умолчанию 48000) — ради длинных разборов
всё и затевалось. Вопрос, случайно начавшийся с этих слов, файлом не станет:
`!контекст html5 canvas тормозит` останется вопросом, потому что совпадать
должно слово целиком.

### Забрать сообщение в личку

`/гем !личка` реплаем на любое сообщение — и его копия придёт вам в личный
диалог с ботом. Полезно для файлов и длинных разборов: в общем топике они
тонут, а у себя всегда под рукой.

```
/гем !личка   (реплаем на файл)     → тот же файл вам в личку
/гем !личка   (реплаем на снимок)   → снимок вам в личку
```

Копия, а не пересылка: `forwardMessage` тащит шапку «переслано из…» и ссылку
на закрытую группу, которая у получателя всё равно не откроется. `copyMessage`
делает самостоятельную копию — с файлом, подписью и разметкой, но без хвоста.
Файл при этом не перезаливается, Telegram копирует его у себя, поэтому даже
тяжёлый документ уходит мгновенно.

⚠️ **Бот не вправе написать первым.** Пока человек не открыл с ним личный
диалог и не нажал «Запустить», Telegram отвечает `403`. В этом случае в топик
придёт ссылка на бота: открыть, запустить, повторить команду.

Словами это не работает — и не заработает: «отправь мне файл в личку»,
сказанное нейросети, упирается в то, что пересылка вообще не её умение.
Модель об этом предупреждена и вместо «я не могу» подскажет команду.

### Длина ответа

Всё, что бот пишет **в чат**, умещается в одно сообщение Telegram — и обычный
вопрос, и `!контекст`, и разбор фотографии, и ответ по присланной книге.
Без этого длинный разбор приезжал простынёй на десяток сообщений подряд,
где ни прокрутить, ни найти начало.

Держится это тремя слоями, потому что одного мало:

1. модель просят уложиться в 3000 знаков и не обрывать мысль;
2. потолок ответа у цепочки скромный — 3000 токенов у основной, 8000
   у `!контекст`;
3. на выходе бот всё равно режет по границе сообщения — знаки модель
   не считает, и обещаниям про длину верить нельзя.

Если ответ не поместился, следом приходит строка с готовой командой: тот же
вопрос, но файлом. В историю и в архив поиска при этом уходит **полный**
ответ — обрезка касается только показа.

Потолки в токенах и почему они такие:

| Путь | Потолок | Переменная |
| --- | --- | --- |
| `/гем` в чат | 3000 | `GEMINI_MAX_OUTPUT_MAIN` |
| `/гем !контекст` в чат | 8000 | `GEMINI_MAX_OUTPUT_THINK` |
| `/гем !файл <формат>` | 8000 | `FILE_MAX_OUTPUT_TOKENS` |
| `/гем !контекст md\|txt\|html` | 48000 | `FILE_ANSWER_MAX_OUTPUT_TOKENS` |

Откуда 3000 на сообщение: 3500 знаков — это примерно 1400–1800 токенов
на русском, потому что кириллица дороже латиницы (около 2,5 знака на токен).
У `!контекст` потолок выше не ради длины, а ради размышлений: flash думает
перед ответом, и мысли тратятся из того же лимита — прижми потолок к размеру
сообщения, и на сам текст места не останется.

**Реплаем файл собирается без нейросети** — берётся текст сообщения как есть.
Это мгновенно и не тратит никаких норм.

⚠️ Вложения **не попадают в архив поиска**: `!найди` ищет по тексту сообщений.
Поэтому вместе с файлом в чат уходит короткая подпись, и в архив ложится она —
чтобы файл потом хотя бы находился по описанию.

### Файлы: книги, статьи, выгрузки

Файл можно просто прислать — в личке достаточно самого файла, в группе нужна
подпись с командой. Без вопроса бот перескажет содержимое, с вопросом — ответит
по нему. Реплаем на уже отправленный файл тоже работает.

| Формат | Как читается |
| --- | --- |
| `.txt`, `.md`, `.csv`, `.log`, `.json`, `.xml`, `.srt` | как текст; `windows-1251` распознаётся и перекодируется |
| `.fb2` | это XML: разметка и обложка в base64 вырезаются — замерено, файл легчает на 85% |
| `.pdf` | нативно, постранично, читает сама модель |
| `.epub`, `.fb2.zip` | отказ с объяснением: нужна распаковка или конвертация |

Три вещи, которые определяют предел:

* **20 МБ** — потолок Telegram: боты не могут скачать файл больше, обойти нельзя;
* **150 000 токенов** (`DOC_MAX_TOKENS`) — предел на один файл, около 450 КБ
  текста или 230 страниц. Ограничивает не память модели: окно у флешей
  1 048 576 токенов. Ограничивает **минутная норма бесплатного тарифа** —
  замерено, что запрос больше 250 000 входных токенов отбивается сразу, и квота
  в ошибке названа прямо: `GenerateContentInputTokensPerModelPerMinute-FreeTier`.
  100 000 и 150 000 проходят за 3–4 секунды. Остаток бюджета намеренно оставлен
  остальным: иначе один человек с книгой блокировал бы модель для всей группы;
* **файл всегда уходит цепочкой флешей**, а не основной цепочкой:
  у Gemma окно 262 144 токена, а PDF она не принимает вовсе.

📌 Текст файла попадает в запрос, но **не в историю** — иначе одна книга занимала
бы контекст следующие триста сообщений. В историю уходит строчка «прислал файл
такой-то» и ответ модели. Поэтому повторный вопрос с приложенным файлом заново
платит за весь файл: дешевле один раз попросить конспект и говорить по нему.

### «Где здесь …» — рамка поверх фотографии

Подпись к снимку, начинающаяся с «!где», уводит его в отдельную ветку: вместо
рассказа о картинке бот обводит найденное прямо на ней. Так же работает **ответ
реплаем на уже отправленное фото** — и для рамок, и для обычных вопросов к нему
(«/гем что тут написано»). Тонкость Telegram: в таком сообщении самой картинки
нет, есть только ссылка на неё, поэтому бот выкачивает снимок отдельно —
без этого запрос уходил бы в модель голым текстом, и она отвечала бы словами
про несуществующую фотографию.

```
[фотография] /гем !где здесь шлем и перчатки
   ↓
[та же фотография с рамками]
🟥 красная — шлем
🟩 зелёная — перчатка
🟦 синяя — перчатка
```

Работают этим модели **Robotics ER**: они обучены показывать, а не
рассказывать, и возвращают координаты, нормированные к 0…1000 — доли кадра,
а не пиксели. Норма у них по 20 запросов в день на модель, поэтому цепочка
здесь тоже с подхватом.

Рамки рисуются вручную: JPEG разбирается в массив пикселей (`jpeg-js` —
чистый JavaScript, без нативных сборок), поверх кладутся линии, всё
собирается обратно. Толщина считается от размера кадра: на снимке в четыре
тысячи пикселей линия в два пикселя не видна. Подписи прямо на картинке
не рисуются — для букв нужен шрифт и растеризатор, а это уже другая
библиотека; вместо этого рамки разного цвета, а расшифровка уходит в подпись.

### Поиск по переписке

`/гем !найди где мы обсуждали деплой` ищет **по смыслу**: находит разговор про
выкатку на сервер, даже если слова «деплой» в нём не было. Ищет только
по своему разделу — топики не смешиваются.

Как это устроено. История в сессии короткая: там лежит ровно то, что влезает
в контекст модели. Для поиска ведётся отдельный архив — каждая реплика
превращается в вектор и дописывается в файл `SEARCH_DIR/<раздел>.jsonl`.
Индексируются и сообщения людей, и ответы бота; команды пропускаются.

* **норма эмбеддингов** — 1000 запросов в день, поэтому реплики копятся
  и уходят пачкой по десять: это до десяти тысяч сообщений в сутки, заведомо
  больше, чем напишет группа;
* **вектор хранится в base64** от `Float32Array`, а не списком чисел: 768
  измерений — это 3 КБ вместо 15 КБ текстом;
* **векторы разных моделей несравнимы.** Замерено: один и тот же текст,
  посчитанный `gemini-embedding-001` и `gemini-embedding-2`, даёт близость
  **−0,03** вместо единицы. Поэтому в каждой записи хранится модель, а поиск
  сравнивает только записи одной модели с запросом, посчитанным ею же. Без
  этого одно срабатывание запасной модели превратило бы выдачу в мусор;
* **пачка отправляется массивом `Content`, а не массивом строк.** У второй
  версии мультимодальная семантика: от массива строк она склеивает все реплики
  в один вектор, потому что считает их частями одного объекта;
* **порогов два.** У эмбеддингов Gemini высокий «пол»: замерено, что
  совершенно несвязанные русские фразы дают близость 0,60–0,65. Поэтому кроме
  абсолютного порога есть относительный — находки слабее лучшей на `SCORE_GAP`
  отбрасываются. Без этого на запрос «что там с кофе» в ответ приезжал бы ещё
  и разговор про миграции базы;
* **задним числом переписка не индексируется**: в архив попадает только то,
  что сказано после включения поиска.

### Выключатель на раздел

`/stop` — и в этом топике бот молчит; `/start` — снова отвечает. Кириллицей то
же самое: `/стоп` и `/старт`. Прав ни у кого не спрашивается: выключить
и включить может **любой участник**. Группа маленькая и своя — договориться
в ней проще, чем ходить к администратору, а тот, кому бот сейчас мешает,
как раз и должен уметь его унять.

Выключатель именно на раздел, а не на бота целиком: в одном топике он нужен
постоянно, в другом мешает разговору. Отдельного кода про топики для этого
не понадобилось — состояние лежит в сессии, а сессия у каждого топика уже
своя (см. `getSessionKey` в `src/bot.ts`).

Молчание останавливает всё: ответы, расход квот и **запись переписки в архив
поиска** — middleware стоит до индексатора. Это не мелочь: выключают бота
обычно ровно затем, чтобы разговор шёл без него, и складывать такой разговор
себе в индекс было бы неожиданно.

Сквозь молчание проходят ровно две команды — включение и, что менее очевидно,
само выключение: молчание в ответ на `/stop` читается как поломка, человек
не понимает, что бот уже выключен, и повторяет. Нажатия кнопок гасятся
всплывающей подсказкой, а не игнорируются: неотвеченный callback крутит
часики в клиенте, пока Telegram не сдастся сам.

### Живой поиск в интернете

`/гем !сеть что нового про Gemini 3` отвечает по свежим страницам и приписывает
снизу ссылки на источники. Не путать с `!найди`: та ищет по нашей же переписке
и бесплатна, эта ходит в интернет и стоит денег.

Это **третье и последнее платное место** в боте — и самое дешёвое: около
$0,004 за запрос против $0,015 за картинку. Отсюда дневная норма
(`WEB_DAILY_LIMIT`, по умолчанию 10 на человека) и то, что поиск включается
словом, а не идёт по каждому вопросу.

**Почему не встроенный поиск Gemini,** с которого начинали. У Gemini есть
grounding with Google Search, и он был реализован первым — но бесплатному
ключу инструмент недоступен: API отвечает, что для этого ключа он не разрешён
(проверено на живом ключе бота 18 августа 2026). Заработает он, если включить
у Google биллинг, — но это ровно такие же деньги, только другому поставщику.

**Почему не DuckDuckGo,** с которого обычно предлагают начать. Официального
поискового API у него нет вовсе. Бесплатный Instant Answer отдаёт карточки
из Википедии, а не выдачу, и на живой вопрос возвращает пустоту. Остаётся
скрейпить HTML, а его DuckDuckGo целенаправленно душит (`202`, `403`) —
и особенно быстро с адресов дата-центров, то есть ровно с нашей VPS.

**Как устроено у OpenRouter.** Поиск здесь не модель, а плагин к обычному
запросу `chat/completions`: найденные страницы подмешиваются в тот же вызов,
и модель, которая ищет, она же и пишет ответ. Второго обращения к нейросети
не нужно — а значит, не нужно и ждать дважды.

Ключевая экономия в том, что **движок поиска выбирается отдельно от модели**,
а цены у движков различаются в разы:

| Движок | Цена за запрос |
| --- | --- |
| `parallel` | **$0,001** — стоит по умолчанию |
| `perplexity` | $0,005 |
| `exa` | $0,007 |

Модель к любому из них подходит любая. По умолчанию — `google/gemini-3.5-flash-lite`
($0,30 и $2,50 за миллион токенов по каталогу на 18.08.2026, то есть около
$0,003 на запрос сверх поиска): на нём же работает половина бота, и по-русски
он отвечает ровно так, как здесь ожидают.

Дешевле есть: `qwen/qwen3.7-flash` — $0,03 и $0,13 за миллион, запрос выходит
$0,0012 вместо $0,004, втрое меньше. В абсолютных деньгах это четверть цента,
поэтому по умолчанию всё же единообразие ответов; кому важнее счёт — меняет
одну строку в `.env`, пересборка не нужна.

Ещё про устройство:

* **своей цепочки моделей здесь нет.** Цепочка в этом боте — про перебор
  бесплатных норм Gemini, а тут платный вызов к другому поставщику: отказ
  показывается человеку как есть;
* **слот нормы возвращается при неудаче.** Норма про потраченное, а не
  про попытки;
* **ответ уходит в историю раздела** наравне с обычными: «а поподробнее?»
  после поиска — естественное продолжение разговора;
* **источников не больше пяти** — в одно сообщение Telegram всё равно
  не влезет.

### Голосовые сообщения боту

Бот слышит голосовые и отвечает по сказанному.

```
в личке:   просто наговорите — отвечу
в группе:  /гем !расшифруй            реплаем на голосовое
           /гем что он просит сделать реплаем на голосовое
           голосовое реплаем на мою реплику — продолжение разговора
```

**Отдельного «распознавания речи» здесь нет.** Запись уходит в модель ровно тем
же путём, что фотография, — вложением в обычный запрос. Из этого следует всё
остальное:

* **это дёшево.** Google считает звук по 32 токена за секунду: минута голосового
  — около 2000 токенов, меньше пары снимков. И, в отличие от озвучки, никакой
  своей отдельной нормы у голосовых нет — они тратят общий пул, а он огромен.
  Ровно поэтому голос в текст обходится несравнимо дешевле текста в голос:
  у TTS-моделей по 10 запросов в сутки на каждую, здесь — сотни;
* **цепочка своя,** `GEMINI_CHAIN_VOICE`. Это та же основная, из которой убрана
  Gemma: звука она не слышит вовсе, и голосовое сорвалось бы на первом же шаге,
  причём безнадёжно — «модель так не умеет» это не «кончилась норма», следующую
  модель цепочка на таком отказе не берёт;
* **расшифровку бот не печатает.** Её и так все слышали, а стена текста поверх
  прозвучавшего только засоряет топик. Модель слышит запись целиком, так что
  отвечает по смыслу, а не по пересказу. Нужна расшифровка — попросите словами:
  `/гем !расшифруй выпиши дословно`;
* **формат приводится к FLAC.** Telegram отдаёт голосовые в OGG с кодеком Opus —
  другого он не отдаёт вовсе, — а Google в списке форматов пишет «OGG Vorbis»:
  контейнер тот же, кодек другой. Обычно Opus проезжает, но «обычно» — плохая
  опора, а отказ по формату неперебираемый. Поэтому запись перекодируется
  в 16 кГц моно FLAC: именно к 16 кГц моно Google приводит любой звук сам, так
  что качество не теряется, а формат становится тем, что записан в документации
  буквально. FLAC, а не MP3, потому что его кодировщик в `ffmpeg` встроенный,
  а MP3 требует libmp3lame — внешней библиотеки, которой в чужой сборке может
  и не оказаться. Нет самого `ffmpeg` — запись уйдёт как есть, и тогда
  как повезёт; в образе он стоит;
* **в историю раздела уходит пометка** «прислал голосовое (0:42)» и ответ бота,
  но не сказанное. Так же устроены и снимки: о чём шла речь, видно из ответа,
  и этого хватает на «а что там дальше по этому поводу».

**Почему в группе нужно слово.** У снимка и файла есть подпись — ею в группе
и обращаются к боту. У голосового подписи нет: большинство клиентов её просто
не даёт написать. Единственный способ показать боту на запись — ответить
реплаем, и в этом реплае должно быть хоть что-то. Вот `!расшифруй` и есть это
«что-то»; если вопрос по записи уже есть, слово не нужно — задавайте вопрос.

Предел длины задаёт Telegram, а не бот: скачивать файлы больше 20 МБ боты
не умеют, для голосового это примерно 40 минут.

### Озвучка голосом

`/гем !скажи <текст>` присылает голосовое. Без текста источник ищется по
убыванию определённости: сообщение, на которое ответили реплаем (любое, не
только своё — попросить озвучить чужую реплику так же естественно), иначе
последний ответ бота в разделе.

* дневная норма у TTS-моделей маленькая, **по 10 запросов на каждую**, поэтому
  здесь та же цепочка с подхватом, что у текста: упёрлись в одну — берём
  следующую. В сумме два-три десятка озвучек в день на всю группу;
* Telegram принимает голосовые **только в OGG/Opus**, а Gemini отдаёт сырой PCM
  (16 бит, моно, 24 кГц). Есть `ffmpeg` — бот перекодирует и пришлёт настоящее
  голосовое, заодно файл выходит вдесятеро легче; нет — завернёт PCM в WAV
  и пришлёт аудиофайлом. В образе `ffmpeg` уже установлен, и его же используют
  голосовые на вход (см. раздел выше);
* разметка Markdown перед синтезом вычищается: «звёздочка жирный звёздочка»
  на слух — мусор. Длинный текст обрезается по границе предложения, о чём бот
  честно пишет в подписи.

**Голос и манера — разные рычаги.** Голос выбирается из закрытого набора
Google: кто говорит. Манера задаётся обычными словами прямо в запросе: как
говорит — и здесь просить можно что угодно.

```
/гем !скажи «низкий» смена закончена            → голос Charon
/гем !скажи «высокий» а вот и я                 → голос Leda
/гем !скажи «шёпотом» только никому не говори   → голос из настроек, но шёпотом
/гем !скажи «как в Warcraft 3» работа не ждёт   → манера, какую опишете
/гем !скажи «низкий, устало» день был долгий    → и голос, и манера сразу
```

Готовые голоса: `низкий` (Charon), `высокий` (Leda), `бодрый` (Puck),
`твёрдый` (Kore), `мягкий` (Aoede), `яркий` (Zephyr), `напористый` (Fenrir),
`уверенный` (Orus). Незнакомое слово ошибкой не считается — оно уходит модели
как описание манеры. Голос по умолчанию задаётся в `GEMINI_TTS_VOICE`.

**Кавычки обязательны, и это не придирка.** Без них не отличить заказ от речи:
`!скажи низкий поклон всем` — это просьба прочитать фразу про поклон,
а не прочитать «поклон всем» низким голосом. Кавычки годятся любые:
«ёлочки», "прямые", 'одинарные'.

Набор голосов у Google со временем меняется, и наш список может отстать.
На этот случай отказ из-за имени голоса не оставляет без озвучки: бот
повторит запрос голосом из настроек.

### Песня с вокалом

`/гем !трек <описание>` присылает музыку с пением. Стиль и слова бот собирает
сам — писать их руками не нужно.

```
/гем !трек грустная песня про дедлайны, женский вокал
/гем !трек полминуты весёлого чиптюна без вокала
/гем !трек секунд десять тяжёлого риффа про пятничный релиз
```

Работает это **в два шага, и первый бесплатный.** Ace-Step ждёт не просьбу
словами, а две отдельные вещи: `style_prompt` — теги про музыку по-английски
(жанр, настроение, инструменты, тип голоса, темп) и `lyrics` — собственно слова
с разметкой структуры, `[verse]`, `[chorus]`, `[bridge]`. Собирает их бесплатный
Gemini на той же лёгкой цепочке, что готовит запросы к рисованию. Только потом
заказывается сам трек — и вот он стоит денег.

* **слова приходят сразу**, отдельным сообщением, пока пишется музыка: их всё
  равно захочется прочесть, а в подпись к аудио они не влезают — у Telegram
  там 1024 знака. Сообщение остаётся в разделе, под ним и подпевают;
* **длительность можно назвать словами** — «полминуты», «секунд десять».
  По умолчанию 30 секунд, и это же потолок (`TRACK_MAX_DURATION`): платится
  секунда готового звука, а не запрос, так что полминуты обходятся как
  картинка. Попросите дольше — запрос урежется до потолка, а настоящая
  длительность будет видна в подписи под треком;
* **без вокала** — скажите «инструментал» или «без вокала»: в запрос уйдёт
  `[inst]`, и модель сыграет без пения;
* **язык вокала** определяется самими словами, отдельного параметра нет.
  Русский замысел даёт русский текст и русское пение;
* **дневная норма — 2 трека на человека** (`TRACK_DAILY_LIMIT`), счёт отдельный
  от картинок. Подпись под треком показывает длительность, цену, время
  генерации и остаток нормы на сегодня.

**Уточняющих вопросов здесь нет,** в отличие от рисования, и это не недоделка.
У картинки вопросы окупаются: пропущенный стиль или кадр видно сразу, а
переделка стоит столько же, сколько попадание. У песни главное — слова, и они
приходят человеку до трека; спрашивать «начинать?» после того, как текст уже
написан, значит удваивать шаги ради того же результата.

Генерация асинхронная: GoAPI отдаёт `task_id`, а бот сам спрашивает «готово?»
каждые три секунды. Вебхук сервис тоже умеет, но боту для этого понадобился бы
адрес, открытый наружу, — а он работает через long polling именно затем, чтобы
обойтись без него. Минуту музыки Ace-Step пишет за 20–40 секунд.

Про ключ, цену и то, почему это вообще платно, — раздел
[Шаг 0, пункт 4](#4-goapi-песни-с-вокалом-платно).

### Разговор перед рисованием

Две картинки в день — это значит, что попадать надо с первого раза, а «нарисуй
кота» с первого раза не попадает. Поэтому между командой и деньгами стоит
бесплатный Gemini: он смотрит, чего в запросе не хватает, задаёт два-три вопроса
кнопками и собирает промпт по правилам Krea. Тратится только подтверждённое.

```
/гем !нарисуй кот-космонавт
   ↓  Gemini на лёгкой цепочке, 1–2 с, бесплатно
1/3. В каком стиле?   [кинематографичный] [мультяшный 3D] [ретро-футуризм]
                      [⏩ Рисуй как есть]
2/3. Где находится кот?
3/3. Какое освещение?
   ↓
🎨 Нарисую вот это: «рыжий кот в скафандре, акварель…»
   Форма: 4:5 — портрет · Примерно $0,015 · Останется на сегодня: 1 из 2
   [1:1] [4:3] [3:2] [16:9]
   [✅ 4:5] [2:3] [9:16]
   [🎨 Рисовать] [✏️ Поправить] [✖️ Отмена]
```

Тонкости, которые заметны не сразу:

* если замысел уже описан подробно, вопросов не будет — сразу подтверждение;
* **форма выбирается кнопкой**, на том же экране и до траты. Переключение
  ничего не стоит: меняется черновик, и то же сообщение перерисовывается.
  Набор кнопок — это `OPENROUTER_IMAGE_ASPECT_RATIOS`, отмечена галочкой
  текущая, а начинается всё с `OPENROUTER_IMAGE_ASPECT_RATIO`. Ввода руками
  нет намеренно: модель понимает только свой список, и «3:4» обернулось бы
  ошибкой `400` уже после нажатия «Рисовать»;
* **`creativity`**. У Krea есть собственное расширение промпта, и по умолчанию
  оно включено (`medium`): модель дописывает стиль и настроение за автора.
  После разговора это вредно — договорились об одном, нарисует другое, — поэтому
  согласованный промпт уходит с `creativity: raw`. А вот «рисуй как есть»,
  наоборот, живёт за счёт дорисовки, и там остаётся `medium`;
* **синтаксис Stable Diffusion не работает**. Веса `(слово:1.5)`, `((слово))`
  и заклинания вроде `8k, masterpiece` Krea читает как обычный текст и рисует
  буквально. Бот вычищает их из запроса и говорит об этом — в том числе из
  промпта, который сочинил помощник: тот сам любит дописать «8k resolution»;
* черновик живёт 30 минут и лежит **по одному на человека**: в общем топике
  рисовать могут двое сразу, чужую кнопку нажать нельзя;
* цепочка для вопросов своя (`GEMINI_CHAIN_DRAW`) и намеренно лёгкая. Задача
  формальная — вернуть JSON с вопросами, — а человек в это время ждёт: замерено,
  что Gemma 31B думает над ней 25 секунд, а flash-lite полторы, и вопросы те же;
* `DRAW_ASK_QUESTIONS=false` возвращает старое поведение: рисовать сразу.

Ключ **один на аккаунт**, а не на модель: сменить `OPENROUTER_IMAGE_MODEL` можно
в любой момент, ничего дополнительно получать не нужно. А вот параметры у моделей
разные, и лишнее поле в запросе — это `400`. Что понимает конкретная модель,
показывает её карточка в списке <https://openrouter.ai/api/v1/images/models>;
пустое значение переменной означает «не отправлять это поле вовсе».

| | `krea/krea-2-medium-turbo` (по умолчанию) | `openai/gpt-image-1-mini` |
| --- | --- | --- |
| `aspect_ratio` | `1:1`, `4:3`, `3:2`, `16:9`, `4:5`, `2:3`, `9:16` — и только они | `1:1`, `3:2`, `2:3`, `auto` |
| `resolution` | только `1K` | ступени есть, но модель их игнорирует |
| `quality` | не понимает | `auto`/`low`/`medium`/`high` |
| `output_format` | не понимает, отдаёт png | `jpeg` — файл в 30 раз легче png |

Пропорцию стоит задавать явно в любом случае — иначе модель выбирает форму сама.
У моделей OpenAI от формы вдобавок напрямую зависит цена: квадрат — 272
оплачиваемых токена, портрет и ландшафт — 400–408, то есть в полтора раза дороже.

Блок можно оставить пустым — тогда отключится только рисование, остальное работает.

## Запуск без Docker: production

```bash
npm ci                  # ставим все зависимости: TypeScript нужен для сборки
npm run build           # компиляция src/ → dist/
npm prune --omit=dev    # опционально: выкинуть dev-зависимости после сборки
NODE_ENV=production npm start
```

Чтобы бот пережил перезагрузку сервера, оформите его как сервис systemd.

**`/etc/systemd/system/serverbot.service`:**

```ini
[Unit]
Description=Telegram AI bot
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
User=deploy
WorkingDirectory=/opt/serverbot
EnvironmentFile=/opt/serverbot/.env
Environment=NODE_ENV=production
ExecStart=/usr/bin/node dist/index.js
Restart=always
RestartSec=5
# Немного безопасности: боту не нужен доступ ко всей файловой системе
NoNewPrivileges=true
PrivateTmp=true
ProtectSystem=full

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now serverbot
sudo systemctl status serverbot
journalctl -u serverbot -f          # логи в реальном времени
```

Альтернатива без systemd — **pm2**:

```bash
npm i -g pm2
pm2 start dist/index.js --name serverbot --time
pm2 logs serverbot
pm2 save && pm2 startup             # автозапуск после ребута
```

## Запуск в Docker: production

```bash
cp .env.example .env
nano .env

docker compose up -d --build      # собрать и запустить в фоне
docker compose logs -f bot        # смотреть логи
docker compose ps                 # статус и health-check
curl http://127.0.0.1:3000/health # проверка живости
```

Ответ health-check:

```json
{"status":"ok","env":"production","uptimeSec":42,
 "bot":"your_bot","providers":[{"id":"gemini","ready":true}]}
```

Управление:

```bash
docker compose restart bot        # перезапустить
docker compose down               # остановить и удалить контейнеры
docker compose up -d --build      # обновить после изменения кода
docker compose pull && docker compose up -d   # обновить базовые образы
```

Что уже сделано за вас в `Dockerfile` и `docker-compose.yml`:

* multi-stage сборка — в финальном образе нет ни исходников, ни TypeScript (~276 МБ);
* запуск от непривилегированного пользователя `node`, а не от root;
* `tini` как init — `docker stop` корректно доходит до Node, бот завершается штатно;
* `restart: unless-stopped` — переживает падение и перезагрузку сервера;
* health-check, ротация логов (3 файла по 10 МБ), лимит памяти 512 МБ;
* порт `3000` публикуется **только на 127.0.0.1** и нужен исключительно
  для health-check — снаружи бот недоступен, входящие соединения ему не нужны.

## Деплой на удалённый сервер

Подойдёт любой VPS с 1 ГБ RAM. Ниже — вариант «Ubuntu + Docker».

### 1. Установить Docker на сервере

```bash
ssh user@your-server-ip
curl -fsSL https://get.docker.com | sudo sh
sudo usermod -aG docker $USER && exit     # перелогиньтесь, чтобы группа применилась
```

### 2. Доставить код

Вариант А — через git (удобно обновлять):

```bash
ssh user@your-server-ip
git clone <адрес-вашего-репозитория> /opt/serverbot
cd /opt/serverbot
```

Вариант Б — скопировать с локальной машины:

```bash
# node_modules и dist не копируем — они соберутся в образе
rsync -av --exclude node_modules --exclude dist --exclude .git \
      ./ user@your-server-ip:/opt/serverbot/
```

### 3. Настроить и запустить

```bash
cd /opt/serverbot
cp .env.example .env
nano .env                    # BOT_TOKEN и ключи нейросетей
docker compose up -d --build
docker compose logs -f bot
```

### 4. Обновление после изменений

```bash
cd /opt/serverbot
git pull                     # или повторный rsync
docker compose up -d --build
```

### 5. Файрвол

Боту нужны только **исходящие** соединения к `api.telegram.org` и к API нейросетей,
поэтому входящие порты открывать не нужно вообще — достаточно оставить SSH:

```bash
sudo ufw allow OpenSSH
sudo ufw enable
```

> **Важно:** один и тот же токен нельзя использовать двумя запущенными ботами
> одновременно — Telegram будет отдавать ошибку `409 Conflict`. Останавливайте
> локальный `npm run dev`, пока бот работает на сервере (или заведите второго
> тестового бота у @BotFather).

## Публикация образа в GHCR

Готовый образ в GitHub Container Registry позволяет разворачивать бота на любой
машине одной командой — без исходников, Node.js и сборки. Нужен только Docker.

Итоговое имя образа: **`ghcr.io/jadykov/serverbot`**
(шаблон — `ghcr.io/<владелец>/<репозиторий>`, всё строчными буквами).

### Способ 1: автоматически через GitHub Actions (рекомендуется)

В репозитории уже лежит `.github/workflows/docker-publish.yml`. Он собирает
образ под **linux/amd64 и linux/arm64** и публикует его при каждом пуше в `main`.
Пуши, где менялись только `*.md`, пропускаются (`paths-ignore`): документация
образ не меняет. Собрать вручную всегда можно кнопкой **Run workflow**.
Токен создавать не нужно — Actions использует встроенный `GITHUB_TOKEN`.

Достаточно запушить workflow в репозиторий:

```bash
git add .github/workflows/docker-publish.yml docker-compose.deploy.yml
git commit -m "Публикация образа в GHCR"
git push
```

Дальше — вкладка **Actions** в репозитории: там видно ход сборки. Первый запуск
занимает ~5 минут (arm64 собирается через эмуляцию), последующие — быстрее
за счёт кэша слоёв.

> В приватных репозиториях сборки расходуют бесплатные минуты Actions
> (2000 в месяц на бесплатном тарифе). Для публичных репозиториев Actions
> бесплатны без лимита. Если минут жалко — уберите `linux/arm64`
> из `platforms` или публикуйте образ вручную (способ 2).

Теги, которые создаёт workflow:

| Тег | Когда появляется | Пример |
| --- | --- | --- |
| `latest` | пуш в `main` | `ghcr.io/jadykov/serverbot:latest` |
| `sha-<хеш>` | каждая сборка | `ghcr.io/jadykov/serverbot:sha-0aaf4da` |
| `1.2.3`, `1.2` | git-тег `v1.2.3` | `ghcr.io/jadykov/serverbot:1.2.3` |

Выпустить версию:

```bash
git tag v1.0.0 && git push origin v1.0.0
```

### Способ 2: вручную со своей машины

Понадобится **Personal Access Token (classic)** с правом `write:packages`:
GitHub → Settings → Developer settings → Personal access tokens → Tokens (classic).

```bash

# 2. Сборщик для мультиарх-образов (создаётся один раз)
```

Только под свою архитектуру (быстрее): уберите `--platform`.

### Сделать образ публичным

**Это обязательный шаг:** при первой публикации пакет создаётся приватным,
и `docker pull` с чужой машины вернёт `denied`.

1. Откройте профиль → вкладка **Packages** → пакет `serverbot`
   (прямая ссылка: `https://github.com/users/jadykov/packages/container/serverbot/settings`);
2. блок **Danger Zone** → **Change visibility** → **Public** → подтвердите ввод имени.

Там же, в **Manage Actions access**, стоит связать пакет с репозиторием, чтобы
последующие сборки могли его перезаписывать (обычно связывается само по метке
`org.opencontainers.image.source`).

Проверка со стороны — без логина в Docker:

```bash
docker pull ghcr.io/jadykov/serverbot:latest
```

### Развернуть на любой VM

На чистой машине нужны только Docker, файл `.env` и один compose-файл:

```bash
# 1. Docker
curl -fsSL https://get.docker.com | sudo sh
sudo usermod -aG docker $USER && exit   # перелогиньтесь
```

```bash
# 2. Скопировать конфигурацию с рабочей машины
scp docker-compose.deploy.yml .env.example user@сервер:~/serverbot/
```

Репозиторий приватный, поэтому скачать файлы через `curl` с
`raw.githubusercontent.com` не получится — только `scp`, `git clone` с ключом
или просто вставить содержимое в редакторе. Если сделаете репозиторий публичным,
сработает и такой вариант:

```bash
curl -O https://raw.githubusercontent.com/jadykov/serverbot/main/docker-compose.deploy.yml
```

```bash
# 3. Ключи и запуск
cd ~/serverbot
mv .env.example .env && nano .env        # впишите BOT_TOKEN и ключи нейросетей
chmod 600 .env

docker compose -f docker-compose.deploy.yml up -d
docker compose -f docker-compose.deploy.yml logs -f
```

Обратите внимание: **сам образ публичный, а репозиторий может оставаться
приватным** — видимость пакета в GHCR настраивается отдельно от репозитория.
Ключей внутри образа нет, они подставляются из `.env` при запуске.

Обновление до свежего образа:

```bash
docker compose -f docker-compose.deploy.yml pull
docker compose -f docker-compose.deploy.yml up -d
```

Совсем без compose — одной командой:

```bash
docker run -d --name serverbot --restart unless-stopped \
  --env-file .env -e NODE_ENV=production \
  ghcr.io/jadykov/serverbot:latest
```

## Переезд на другой сервер

Развернуть бота с нуля — это разделы выше. Здесь про другое: как перевезти
**уже работающего** бота, ничего не потеряв. Сам код переносить не нужно (он
есть в git и в образе), а вот два места переживут переезд только руками.

### Что именно нужно перевезти

| Что | Где лежит | Что потеряется, если забыть |
| --- | --- | --- |
| Ключи и настройки | `.env` | Бот просто не запустится: `.env` в git не хранится (см. [Безопасность](#безопасность)) |
| История разделов | `data/sessions/**` | История диалога в каждом топике — бот перестанет помнить, о чём шла речь |
| Счётчик картинок | `data/sessions/image-quota.json` | Дневные лимиты обнулятся, и `!нарисуй` снова даст всем по полной норме |
| Архив для поиска | `data/search/*.jsonl` | `/гем !найди` начнёт искать с чистого листа: старую переписку бот заново **не** проиндексирует, только новую |

Пути настраиваются переменными `SESSION_DIR` и `SEARCH_DIR`; если вы их меняли —
переносите то, что указано у вас.

### Порядок действий

**1. Остановить бота на старой машине.** Не «потом», а первым делом: один токен
в двух живых экземплярах даёт `409 Conflict`, и оба начинают терять апдейты.

```bash
docker compose down                  # или -f docker-compose.deploy.yml down
```

Если бот запускался без Docker — остановите `npm start` (`Ctrl+C` или
`systemctl stop`, смотря как он у вас поднят).

**2. Забрать `.env` и данные.** Со старой машины:

```bash
scp .env user@новый-сервер:~/serverbot/.env
rsync -av data/ user@новый-сервер:~/serverbot-data/
```

Если бот на старом сервере работал в Docker, `data` лежит не в файловой системе
хоста, а в томе — вынимаем оттуда:

```bash
docker run --rm -v serverbot_bot-data:/src -v "$PWD":/dst alpine \
  tar czf /dst/bot-data.tgz -C /src .
scp bot-data.tgz user@новый-сервер:~/
```

Имя тома — `<имя проекта>_<имя тома>`, то есть `serverbot_bot-data`
(`docker volume ls` покажет точное).

**3. Создать контейнер на новом сервере, но не запускать** — по инструкции
[«Развернуть на любой VM»](#развернуть-на-любой-vm), только вместо `up -d`
командой `create`. Так том появится, а бот ещё не начнёт писать в пустые сессии:

```bash
cd ~/serverbot && chmod 600 .env
docker compose -f docker-compose.deploy.yml create
```

**4. Залить данные в том:**

```bash
# из папки, скопированной rsync-ом
docker run --rm -v serverbot_bot-data:/dst -v ~/serverbot-data:/src alpine \
  sh -c 'cp -a /src/. /dst/'

# либо из архива, снятого с тома
docker run --rm -v serverbot_bot-data:/dst -v ~:/backup alpine \
  tar xzf /backup/bot-data.tgz -C /dst
```

**5. Запустить и проверить:**

```bash
docker compose -f docker-compose.deploy.yml up -d
docker compose -f docker-compose.deploy.yml logs -f
```

Проверка, что переехало именно состояние, а не пустышка: `/гем !найди` должен
находить старые сообщения, а разговор в топике — продолжаться с того же места.

### Вариант проще: данные рядом с compose-файлом

Если возня с томами раздражает, замените в `docker-compose.deploy.yml`
(или в `docker-compose.yml`) том на обычную папку хоста:

```yaml
    volumes:
      - ./data:/app/data      # вместо bot-data:/app/data
```

Тогда состояние бота — это просто `~/serverbot/data`, а переезд и бэкап
сводятся к одному `rsync -av data/ user@сервер:~/serverbot/data/`. Секцию
`volumes:` в конце файла в этом случае можно удалить. Плата за удобство —
контейнер пишет файлы от своего пользователя, и права на папке иногда
приходится поправлять (`sudo chown -R 1000:1000 data`).

### Если репозиторий приватный

Образ в GHCR при первой публикации тоже приватный, и `docker pull` на новой
машине ответит `denied`. Либо сделайте пакет публичным
([как](#сделать-образ-публичным) — ключей в образе нет, они подставляются из
`.env`), либо залогиньтесь на сервере с Personal Access Token, которому дано
право `read:packages`:

```bash
docker login ghcr.io -u jadykov
```

### Смена архитектуры

Образ собирается сразу под `linux/amd64` и `linux/arm64`, так что переезд с
обычного VPS на ARM (Hetzner CAX, Oracle Ampere) не требует ничего особенного:
`docker pull` сам возьмёт нужный вариант. Данные в `data/` — обычный JSON и
JSONL, они от архитектуры не зависят.

## Работа в группах и топиках

Бот полностью работает в группах и супергруппах, в том числе в форумах с топиками.

**Как добавить:** откройте группу → «Добавить участника» → найдите бота по username.
Права администратора ему не нужны.

**Куда он отвечает:** всегда туда же, где его спросили — реплаем на сообщение
с запросом и в тот же топик форума. За это отвечает `src/middlewares/reply.ts`,
который подставляет `reply_parameters` и `message_thread_id` во все ответы.
История диалога в форумах ведётся отдельно для каждого топика (ключ сессии
`chat_id:thread_id`, см. `src/bot.ts`).

**На что реагирует:** только на команды. Обычные сообщения в группе бот
игнорирует молча. Команда, адресованная другому боту (`/гем@другой_бот`),
тоже игнорируется.

### Важно: `/гем` против `/gem` в группах

Telegram считает командой только латиницу — имя `гем` API отклоняет
(`setMyCommands` → `BOT_COMMAND_INVALID`), и клиент не размечает такое слово
как команду. Отсюда практическое следствие:

| | `/gem запрос` | `/гем запрос` |
| --- | --- | --- |
| В личке | работает | работает |
| В группе с privacy mode (по умолчанию) | работает | **бот не получит сообщение** |
| В группе с отключённым privacy mode | работает | работает |
| Видна в меню команд | да | нет |

По умолчанию у бота включён privacy mode: в группах Telegram присылает ему
только команды, адресованные ему самому. Чтобы `/гем` работал и в группах:

1. @BotFather → `/setprivacy` → выберите бота → **Disable**;
2. **удалите бота из группы и добавьте заново** — без этого настройка не применится.

Проверить текущее состояние: `can_read_all_group_messages` в ответе

```bash
curl -s "https://api.telegram.org/bot<ВАШ_ТОКЕН>/getMe"
```

Если менять настройку не хочется — в группах просто используйте `/gem`.

## Разметка ответов

Нейросеть пишет обычный Markdown, а Telegram понимает только свой набор тегов.
Модуль `src/format.ts` конвертирует одно в другое:

| Markdown от модели | Что увидит пользователь |
| --- | --- |
| `**текст**`, `__текст__` | жирный |
| `*текст*`, `_текст_` | курсив |
| `~~текст~~` | зачёркнутый |
| `` `код` `` | моноширинный |
| ` ```js … ``` ` | блок кода с подсветкой языка |
| `[текст](https://…)` | ссылка |
| `> цитата` | блок цитаты |
| `- пункт` | `• пункт` |
| `## Заголовок` | жирная строка |

Почему конвертация именно в HTML, а не в MarkdownV2: в MarkdownV2 нужно
экранировать полтора десятка символов, и один пропущенный ломает всё сообщение.
В HTML экранируются всего три символа — `&`, `<`, `>`.

Защита от сюрпризов: если Telegram всё же отклонит разметку, бот повторит
отправку обычным текстом — пользователь получит ответ в любом случае.
Длинные ответы режутся по границам строк, причём блок кода не разрывается:
он закрывается в одном сообщении и заново открывается в следующем.

Таблиц в Telegram нет, поэтому в системном промпте модели прямо запрещены
таблицы, вложенные списки и HTML-теги (см. `src/services/gemini.ts`).

### Смайлики вместо вёрстки

В Telegram нет ни выносок, ни цветных плашек, ни таблиц — взгляду не за что
зацепиться в сплошном тексте. Поэтому модели разрешён **строгий набор значков,
и каждый значит ровно одно**:

| Значок | Когда |
| --- | --- |
| ⚠️ | предупреждение: сломается, потеряется или обойдётся дорого |
| 📌 | главный вывод, если ответ длинный |
| ✅ ❌ | «так верно» и «так неверно» — только парой, в противопоставлении |
| 💡 | неочевидный приём, который экономит время |

Правила намеренно жёсткие: только в начале строки, не больше одного на строку,
не в заголовках, не в конце строки и не подряд. В коротком ответе на две-три
строки значков нет вовсе. Работает это, только пока их мало и каждый закреплён
за смыслом; как только значки становятся настроением, читать снова приходится
подряд — то есть весь смысл теряется.

Правила оформления **дописываются к инструкции всегда** — в том числе к тем
служебным вызовам, где роль своя: сборка файла и разбор замысла перед
рисованием. Иначе такой вызов начинал отвечать таблицами и HTML-тегами,
которые Telegram показать не может.

Своей роли на раздел («промпт топика») у бота нет: она была и убрана. На
небольшую группу ею не пользовался никто, а стоила дорого — команду с текстом
надо было помнить, справку она загромождала, и она же ломала ожидания: ответы
в одном топике вдруг оказывались не такими, как в соседнем, и причина была
не видна.

## Как проверить, что всё работает

По возрастанию сложности — так проще всего понять, на каком уровне сломалось:

1. **Процесс жив:** `curl http://127.0.0.1:3000/health` → `{"status":"ok",...}`
2. **Апдейты доходят:** отправьте боту `/marco` → `🌊 Polo!`
   (или просто напишите `marco` без слэша)
3. **Ответы уходят и Telegram отвечает быстро:** `/ping` → задержка в миллисекундах
4. **Ключи и конфигурация на месте:** `/test` → список ✅/⚪️ по каждому провайдеру
5. **Нейросеть реально отвечает:** `/test ai` → живой запрос к модели
6. **Основной сценарий:** `/гем расскажи анекдот про программиста`
7. **Разметка:** `/гем покажи пример кода на python с пояснением` →
   должны прийти жирный текст, список и блок кода с подсветкой
8. **Картинки:** `/гем !нарисуй кот-космонавт, акварель`
9. **Песни:** `/гем !трек десять секунд весёлого чиптюна` — короткая просьба
    и стоит полцента, а проверяет весь путь: ключ, заказ, ожидание, отправку
10. **Группа:** добавьте бота в группу и отправьте `/gem привет` — ответ должен
    прийти реплаем на ваше сообщение; в форуме — в том же топике

## Переменные окружения

Вся конфигурация бота задаётся только переменными окружения — в коде нет ни одного
захардкоженного ключа. Читает их `src/config.ts`, там же лежат значения по умолчанию
и проверки: при неверной конфигурации бот не стартует, а печатает понятный список
проблем.

### Минимум для запуска

Обязательна ровно одна переменная — токен бота. Всё остальное включает функции:

```dotenv
BOT_TOKEN=1234567890:AAH...          # обязательно, от @BotFather
GEMINI_API_KEY=AIza...               # чтобы работал /гем и разбор картинок
OPENROUTER_API_KEY=sk-or-...         # чтобы работало «/гем !нарисуй» (платно)
```

Если ключа нейросети нет, бот всё равно запустится: команда просто ответит
подсказкой, чего не хватает. Проверить, что видит бот, — команда `/test`.

### Четыре способа передать переменные

**1. Файл `.env` — разработка и docker compose**

Самый частый вариант. Файл лежит рядом с `package.json`, в git не попадает.

```bash
cp .env.example .env
nano .env
npm run dev        # dotenv подхватит файл автоматически
```

Compose-файлы (`docker-compose.yml`, `.dev.yml`, `.deploy.yml`) читают тот же
`.env` через `env_file` — отдельно ничего настраивать не нужно.

**2. Флаги `docker run`**

```bash
docker run -d --env-file .env \
  -e LOG_LEVEL=debug \
  ghcr.io/jadykov/serverbot:latest
```

Значение из `-e` перекрывает значение из `--env-file`.

**3. systemd — запуск без Docker**

```ini
[Service]
EnvironmentFile=/opt/serverbot/.env
Environment=NODE_ENV=production
```

**4. Секреты CI/облака**

В GitHub Actions, Kubernetes, Fly.io и т.п. переменные подставляются платформой.
Ничего менять в коде не нужно: приложение просто читает `process.env`.

### Правила синтаксиса `.env`

```dotenv
# комментарий
BOT_TOKEN=1234567890:AAH...      # без кавычек и без пробелов вокруг =
ADMIN_IDS=111111111,222222222    # список — через запятую, без пробелов
GEMINI_THINKING=                 # пустое значение = «не задано»
```

Частые ошибки: пробелы вокруг `=` (`BOT_TOKEN = 123` не сработает), кавычки
вокруг значения (попадут внутрь строки), перевод строки в середине токена
после копирования.

### Безопасность

* `.env` перечислен в `.gitignore` и в `.dockerignore` — он **не попадает
  ни в репозиторий, ни внутрь образа**. Образ можно публиковать публично:
  ключей в нём нет, они подставляются при запуске контейнера.
* На сервере ограничьте доступ к файлу: `chmod 600 .env`.
* Ключ утёк — отзовите его (@BotFather → `/revoke`, AI Studio → удалить ключ)
  и просто перезапустите контейнер с новым значением.

### Полный список

| Переменная | По умолчанию | Описание |
| --- | --- | --- |
| `BOT_TOKEN` | — | **Обязательно.** Токен от @BotFather |
| `DROP_PENDING_UPDATES` | `true` | Игнорировать апдейты, накопившиеся за простой |
| `SERVER_HOST` / `SERVER_PORT` | `0.0.0.0` / `3000` | Адрес HTTP-сервера с `/health` |
| `GEMINI_API_KEY` | — | Ключ Google Gemini |
| `GEMINI_MODEL` | `gemini-flash-latest` | Модель Gemini (алиас или закреплённая версия) |
| `GEMINI_THINKING` | — | «Размышления»: число (бюджет токенов, Gemini 2.5) или `minimal`/`low`/`medium`/`high` (Gemini 3.x). Пусто — параметр не отправляется |
| `GEMINI_BASE_URL` | — | Адрес прокси вместо `generativelanguage.googleapis.com`. Нужен, если Google не обслуживает IP сервера |
| `GEMINI_CHAIN_MAIN` | см. `.env.example` | Цепочка моделей для всего основного: разговор, картинки, документы |
| `GEMINI_CHAIN_THINK` | см. `.env.example` | Цепочка для `/гем !контекст` — дневная норма невелика |
| `GEMINI_MAX_OUTPUT_MAIN` | `3000` | Потолок ответа в чат для основной цепочки — под одно сообщение Telegram |

## Как добавить свою нейросеть

1. Создайте `src/services/my-ai.ts` и реализуйте интерфейс `TextProvider`
   (или `ImageProvider`) из `src/types.ts`:

```ts
export class MyProvider implements TextProvider {
  readonly id = 'myai';
  readonly title = 'Моя нейросеть';
  readonly setupHint = 'Добавьте MYAI_API_KEY в .env';

  get isConfigured(): boolean {
    return Boolean(process.env.MYAI_API_KEY);
  }

  async generateText(prompt: string): Promise<string> {
    /* запрос к вашему API */
    return 'ответ';
  }
}
```

2. Добавьте её в массив в `src/services/registry.ts`:

```ts
export const textProviders: TextProvider[] = [
  new GeminiProvider(),
  new OpenAiCompatibleProvider(),
  new MyProvider(),   // ← новая строка
];
```

Всё: провайдер появится в `/status` и `/test`, а бот сможет на него
переключиться. Менять команды не нужно.

## Траблшутинг

**`409 Conflict: terminated by other getUpdates request`**
С одним токеном запущено два экземпляра бота. Остановите лишний
(`docker compose down`, `pm2 stop`, локальный `npm run dev`) и подождите ~1 минуту.

**`401 Unauthorized`**
Неверный, отозванный или обрезанный `BOT_TOKEN`. Проверьте его в `.env`
(без кавычек и пробелов), при необходимости получите новый: @BotFather → `/mybots`.

**Бот запустился, но молчит**
Если на этом токене когда-то настраивали приём апдейтов по HTTP-адресу, Telegram
не отдаст их через `getUpdates`. Бот на старте сам сбрасывает такую настройку
(`deleteWebhook` в `src/index.ts`), проверить можно так:
`curl "https://api.telegram.org/bot<ТОКЕН>/getWebhookInfo"` — поле `url` должно быть пустым.

**В группе не работает `/гем`, а `/gem` работает**
Ожидаемое поведение: кириллица не является командой для Telegram, и при
включённом privacy mode такое сообщение боту просто не доставляется.
Решение — см. [Работа в группах и топиках](#работа-в-группах-и-топиках).

**В группе бот не реагирует на обычные сообщения**
Так и задумано: в группах бот отвечает только на команды, иначе он вклинивался бы
в каждую беседу (см. конец `src/commands/ai.ts`).

**Вместо ответа пришёл JSON вида `{"action": "dalle.text2im", ...}`**
Так выглядит попытка модели вызвать инструмент, которого у неё нет: она
подражает другим ассистентам, где рисование встроено. Чаще всего это ловилось
на «/гем нарисуй ...» без восклицательного знака — то есть на обычном вопросе
«нарисуй мне кота», адресованном текстовой модели. В системную инструкцию
добавлена оговорка, что инструментов нет и что рисование живёт в `/гем !нарисуй`
(см. `NO_TOOLS_RULES` в `src/services/gemini.ts`). Если такое всё же повторится
на какой-то модели — там же и правится, одной фразой.

**`Gemini отклонил запрос (400): Request contains an invalid argument`**
Модель не понимает какой-то параметр запроса. Практически всегда виноват
`GEMINI_THINKING`: у Gemini 2.5 «размышления» задаются числом (`thinkingBudget`),
у Gemini 3.x — уровнем (`thinkingLevel`), и значение «не от того поколения»
модель отвергает. Оставьте `GEMINI_THINKING` пустым — тогда параметр не
отправляется вовсе и запрос корректен для любой модели.

**`User location is not supported for the API use` (400)**
Google отклоняет запрос по **IP-адресу отправителя**, а не по ключу и не по
настройкам. Он блокирует диапазоны многих хостингов целиком: массово
сообщают про Hetzner, часть французских и даже американских VPS. Локально при
этом всё работает — потому что запрос уходит с другого адреса.

Как убедиться, что дело именно в адресе: выполните один и тот же запрос
с сервера и с домашней машины —

```bash
curl -s -o /dev/null -w "%{http_code}\n" -X POST \
  "https://generativelanguage.googleapis.com/v1beta/models/$GEMINI_MODEL:generateContent" \
  -H "x-goog-api-key: $GEMINI_API_KEY" -H 'content-type: application/json' \
  -d '{"contents":[{"role":"user","parts":[{"text":"привет"}]}]}'
```

`200` дома и `400` на сервере — вопрос закрыт, проблема в IP. Варианты:

1. **Прокси в разрешённом регионе.** Поднимите тонкий релей (Cloudflare Worker,
   Vercel Function, любой VPS в США) и укажите его в `.env`:
   `GEMINI_BASE_URL=https://ваш-прокси`. Минимальный воркер — просто подмена хоста:

   ```js
   export default {
     async fetch(request) {
       const url = new URL(request.url);
       url.host = 'generativelanguage.googleapis.com';
       return fetch(new Request(url, request));
     },
   };
   ```

   Важно: помогает, только если у самого прокси адрес в поддерживаемом регионе —
   serverless-платформы стоит явно привязать к региону США.

2. **Другой провайдер вместо Gemini.** В боте уже есть OpenAI-совместимый
   клиент: например, OpenRouter отдаёт те же модели Gemini и не блокирует VPS.
   В `.env`: `OPENAI_BASE_URL=https://openrouter.ai/api/v1`,
   `OPENAI_API_KEY=...`, `OPENAI_MODEL=google/gemini-2.5-flash`. Работать будет
   и подставить его в реестр вместо Gemini (`/гем` жёстко привязана к прямому API Google).

3. **Сменить хостинг.** Лотерея: у одного провайдера блок, у соседнего нет,
   иногда различаются даже площадки одного провайдера.

Оплата тарифа проблему не гарантирует: есть сообщения, что и платные ключи
отклоняются с тех же адресов.

**`Модель «...» недоступна для вашего ключа` (404)**
Опечатка в `GEMINI_MODEL` либо модель вывели из обращения — Google периодически
закрывает старые версии («no longer available to new users»). Посмотрите
актуальный список (команда в разделе про ключи) или поставьте плавающий алиас
`gemini-flash-latest`.

**`Gemini отклонил ключ` / запросы к Gemini не проходят**
Проверьте ключ в [AI Studio](https://aistudio.google.com/apikey). Учтите, что
Gemini API доступен не во всех странах — на сервере в неподдерживаемом регионе
запросы будут падать по таймауту или с ошибкой доступа. Решение: сервер в
поддерживаемом регионе либо использование OpenAI-совместимого провайдера.

**«На балансе OpenRouter закончились деньги» (402)**
Генерация картинок платная, и баланс кончился. Пополните счёт на
<https://openrouter.ai/credits>. Порядок расхода: одна картинка в `low` — около
полуцента, то есть пять долларов это примерно тысяча изображений. Фактическую цену
каждого вызова бот пишет в подписи под картинкой — по ней и считайте.

**`/гем !нарисуй` отвечает «нейросеть не подключена»**
Не заполнен `OPENROUTER_API_KEY`. Бесплатной альтернативы здесь нет: у Google все
модели генерации изображений недоступны на бесплатном тарифе.

**Ответ пришёл от «запасной модели»**
Так и задумано: у первой модели в цепочке кончилась дневная норма либо её имя
устарело, и запрос подхватила следующая. Если это происходит постоянно — сверьте
`GEMINI_CHAIN_MAIN` со списком на <https://aistudio.google.com/rate-limit>.

**После обновления бот забыл настройки разделов**
Каталог сессий не на томе. В `docker-compose.yml` том `bot-data` уже описан;
при запуске без Docker проверьте `SESSION_DIR`.

**Внутри Docker не срабатывает hot-reload**
Раскомментируйте `CHOKIDAR_USEPOLLING: "true"` в `docker-compose.dev.yml`
(типично для WSL2 и сетевых файловых систем).

**`Ошибки конфигурации: BOT_TOKEN не задан`**
Нет файла `.env` рядом с `package.json` либо переменная пустая.
`cp .env.example .env` и заполнить.

**Слишком много логов / слишком мало**
`LOG_LEVEL=debug` покажет каждый апдейт и тайминги запросов к нейросетям,
`LOG_LEVEL=warn` оставит только проблемы.
